# ZCode 动态工作流

0.6.2 入口：会话第二排 **对话｜轨迹｜上下文｜工作流｜编队** 中的 **工作流**，内容在中间主区域展示。默认是以真实阶段分组、代理任务节点和依赖连接为主体的图形工作台；顶部选择运行／已保存流程，脚本按需编辑，阶段、四种图、节点日志、结果与产物均保留。画布支持缩放、适应窗口和键盘选择节点。没有工作流右侧栏或输入框入口，聊天卡只显示真实进度摘要。切换主视图时在插件内存中保留当前会话未保存编辑与编辑器开关；刷新或卸载前仍需主动保存。具体安装与视觉验收状态见 [验收记录](<verification.md>)，不能用源码或注册成功代替界面通过。

这不是将脚本交给普通任务队列：插件移植了 ZCode 的 TypeScript 编译器、schema 合成、四种分析图、日志重放引擎和子进程运行器。DSH 适配层负责真实子 Agent、权限、模型路由、持久化和界面。来源及修改见 [上游声明](../vendor/zcode/PROVENANCE.md)。

## 原生 Teams 与标准子代理（0.4.0）

ZCode 核心和依赖已内置并随插件分发，**不需要额外安装、启动 ZCode 应用或连接 ZCode 服务**。

- ZCode 仍负责依赖、并发准入、结构化结果和日志重放；DSH 原生 Teams / subagents 负责实际成员、目录、消息及生命周期。当前 profile 必须启用这两项宿主能力。
- 每次运行有独立的程序化协调会话；它不调用模型。Actor 对应原生队友，同一运行恢复复用同一成员，修订的新运行拥有新的团队，避免永久成员名称跨运行累积。
- 每个实际执行的 ask 对应原生任务。任务板是执行状态投影，不反向调度 ZCode；只在引擎确认结果后完成任务。启动和缓存重放会根据引擎日志校准中断时未同步的任务。
- 初始化不调用模型。活动 ask 可以收到队友消息；空闲消息保留为上下文，等下次 ZCode ask 处理，不能绕过引擎自行执行工具。Actor 不能自行派生另一套团队或修改受管任务状态。
- 原生服务的成员、任务数、激活容量限制仍生效；达到限制会明确失败，不偷偷退回未受管子会话，也不修改你的全局限制。面板并发数不代表能突破原生容量。
- **节点与日志 → DSH Teams / Subagents** 显示真实团队会话、成员及 actor 关联；节点实例带原生任务 ID。当前安装版本为 **0.6.2**，使用第二排“工作流”图形工作台和聊天进度摘要，不注册工作流右侧栏。并行、消息随机值、任务状态、停止恢复和修订缓存的真实实跑证据来自 0.4.2，见 [验收记录](<verification.md>)；0.6.0 独立设计复核为 fix，0.6.1 修正后的用户桌面截图已见结构改善，但最终独立视觉判定和窄尺寸复验仍未完成。本轮不再调用付费模型，小屏与后端实跑不混记。
- 成员按实际 ask 按需建立；仅复用缓存的 actor 不自动生成新成员。需要原生消息接收方时，先让它完成一次明确的就绪 ask。停放消息不保证异步边界上的严格 FIFO；显式停止会按原生语义取消未处理输入。

## 构建与安装

运行环境需支持 `node:sqlite` 的 Node.js 22.13 或更新版本。当前验收环境为 Node.js 26。源码仓库保留生成代码；修改源码后必须重建再安装。

```bash
pnpm install --ignore-scripts
pnpm run build
pnpm run selfcheck
```

用 DSH 的插件管理器，将此目录作为 bundle 安装。已有同名 bundle 时先正常移除再安装，数据不会随移除插件删除。插件安装结果必须为 `application: applied`。安装操作影响当前 profile 的所有会话；不要在运行期间替换插件，替换会停止其拥有的运行。

## 编写与运行

1. 新建或选择已保存流程，填写 TypeScript 函数体、JSON 对象参数及并发数（1–64）。
2. 执行模型可按会话设置选择，或显式选择获准的子 Agent 模型。首次启动固定模型绑定；恢复不会默默换模型。模型需要有有效登录或凭据。
3. 点击 **分析流程**，检查诊断、脚本和流程图。
4. 点击 **确认并运行** 才会启动新流程。模型工具的 `create` 只生成待确认草稿。
5. 通过依赖图、执行顺序、控制流、阶段交接查看静态结构和实际节点状态。点击节点查看实例、输出或错误；记录较多时可加载更多。

```ts
interface Finding { summary: string; risks: string[] }
const reader = agent("调查员", { system: "只读检查，返回结构化结论。" });
phase("调查");
const finding = await reader.ask<Finding>("说明当前项目入口与风险。");
report(finding);
phase("复核");
const review = await agent("复核员").ask(JSON.stringify(finding));
await artifact.markdown("review", review, { title: "复核结果", primary: true });
return { finding, review };
```

`agent()` 是持久具名会话，同一 actor 的多次 `ask` 复用上下文。可用 `Promise.all`、循环、`future`、`channel` 表达动态并行与流。完整 facade 从面板 **API 说明** 或 `zcode_workflow` 的 `help` 获取，避免猜测 API。

常驻说明只保留工具用途、明确请求工作流才使用、先 `action=help` 及人工门禁；详细脚本 API 仍在原有 help 中。已有 `tool_help` 可读取工具说明，但当前宿主没有跨提供方通用的 schema 延迟加载层，因此本工具不设置 `deferLoading`：Codex 仍发送完整参数，已安装的 GLM 适配器会拒绝该标记。本轮仅缩短说明，不改变参数结构，也不声称参数主体或首轮真实模型 token 已缩减。

## 停止、恢复与修订

- **停止运行**：取消拥有的子 Agent/命令，等待收口后保留日志。
- **断点恢复**：从同一实例的持久日志重放。已完成的节点复用已记录结果，不重新执行；因此读取文件也返回原节点记录，而不是自动读取新内容。
- **修改后续跑**：重新分析脚本，创建关联前驱的新实例；由上游缓存匹配规则决定哪些前缀可复用。参数或步骤变化可能使匹配失效，不能假设任何修订都不重新执行。
- **中断操作待核对**：Host 或工具中断后，外部操作可能已发生但未记录结果。此时默认禁止恢复重发。只有确认未完成时选择重试；若已完成，填写经过核实并符合节点 schema 的 JSON 结果。该决定会持久记录。

恢复不提供外部系统的 exactly-once 保证。写数据库、支付、发布等操作仍需要业务侧幂等键和回查；不要因为界面显示停止就认定外部写入没有发生。

## 提问、留白与产物

- Actor 可调用 `escalate` 提问，面板回答后继续，其他 actor 不必停止。
- `await hole<number>("值", "说明")` 会暂停该处。面板 **填入代码** 接收 TypeScript 代码体，例如 `return 9;`，不是 JSON 值。补全后仍经过上游编译和站点稳定性校验。
- `report(item, artifactId)` 驱动表格、指标、图表和看板。复用上游归约器：表格按 key 更新；指标各字段取最近有效值；看板同 key 卡片移动；图表支持声明的线性/对数轴和基准线。
- Markdown 以文本显示并可下载；文件以附件下载，禁止在宿主域执行 HTML/SVG。报告和节点分页读取，较大的日志不必一次全部渲染。
- 保存范围为当前项目或全局。保存的是脚本，不包含用户凭据；新运行仍需确认当前参数和权限。

## 权限与数据

- 子 Agent 继承父会话工作区、沙箱覆盖、适用工具可见性及模型允许列表；子会话不自行发起更宽审批。
- `world.run` 经原生 Bash 工具执行链，保留守卫、审批及沙箱；超时提升为后台作业时由所属会话清理，未知结果保持待核对，不能自动重试。
- 工作区读取经父作用域文件/命令 provider；文件产物限制在运行捕获的工作目录内。私有日志不写入项目。
- 状态默认位于 `$DSH_HOME/composer-assist/workflows/workflow.sqlite`，未设置 `DSH_HOME` 则使用 `~/.dsh`。SQLite 使用 WAL 与 synchronous FULL。运行脚本、参数、提问、输出及工具证据可能含敏感数据；按同等敏感度保护该目录。
- 分析在独立 Worker 内执行，最多约 10 秒、384 MiB，最多排队 8 项；超过限制拒绝，不阻塞 Host 主线程。工作流脚本源码上限 512 KiB。
- Node `vm` 不是 OS 安全边界。仅运行经审阅、确认的脚本；项目操作仍以 DSH provider 的实际隔离能力为准。

## 验收

`pnpm run selfcheck` 不调用付费模型，覆盖编译资源边界、驱动协议、命令守卫及中断清理、跨进程停止/恢复、具名 actor 缓存修订、channels、留白、提问、报告分页、产物和未知结果 accept/retry。

真实 DSH 验收另已完成：GLM 两 actor 并行、typed submit、同 actor 复用；面板分析、四图入口、保存、运行、停止、显式核对后恢复、修订关联、Markdown 下载；同一原生 actor 在留白处停止，恢复并填代码后完成第二个 ask。上游核心 1,983 项分别取得通过证据（初轮超时项单独放宽时间重跑），运行器全套 98 项通过。
